# ColorUp v2 implementation

User requested autonomous completion, a clean Material You interface with sections,
categories and sliders, and correct LSPosed/Vector scope recommendations. Target:
Galaxy A35 5G / One UI 8.5. Preserve existing settings and package ID dev.colorup.

Implementation choices: retain Kotlin / Android Views, use Material 3 components
and dynamic day/night colours. Dashboard, searchable categorized transitions,
focused detail editor, presets and setup/diagnostics. Persist drafts across rotation
and navigation; explicit Save; immediate disable-all. Remove blocking automatic su
export (the content provider is the runtime transport); user-document JSON backup.

1. Establish a reproducible JDK17/SDK36 build and Gradle wrapper. Baseline tests.
2. Pin codec failures with tests: unsupported future schema, oversized inputs,
   non-finite values, canonical encode, independent copies and endpoint continuity.
   Fix validation and use one capability catalog for UI/runtime descriptions.
3. Material 3 theme/resources and new navigation/editor. Only expose live controls
   supported by each hook; offer explicitly labeled preview controls for pending
   transitions. Accurate preview uses the same math as runtime. Test navigation,
   editing/save, kill switch, restoration and import errors on Android.
4. Legacy scope metadata: SystemUI only (no Launcher hooks exist). Setup explains
   framework enable/scope/reboot and distinguishes recorded connection from support.
   Record installed hooks and runtime version, offload config reads to a worker,
   fail closed if bridge disappears; avoid per-frame resource/stack overhead where
   disabled. No guessed Launcher or system_server hooks without firmware evidence.
5. Build/test/lint; run Android emulator, inspect screenshots and exercise actions;
   inspect packaged manifest/scope/assets. Update docs and changelog, deliver APK,
   source branch and reviewable pull request.

Review focus: v1 schema migration; invalid/nonfinite/import data; draft loss;
unsupported controls represented as working; stale heartbeat; UI-thread blocking;
missing manifest scope; spring endpoint discontinuity; provider authorization.

Completion boundary: buildable v2 UI, corrected scoping and verified regressions.
Retail Samsung hook compatibility requires the user's exact firmware and on-device
validation; do not claim all 18 transitions work from emulator evidence.

## Execution evidence

- Baseline regression run: 3 new tests failed for future schema, nonfinite export
  and spring rest endpoint. All fixed; final unit suite 11/11 passed.
- APK and test APK assembled with JDK 17 / SDK 36; target SDK 36.
- Android lint completed with 0 errors (remaining advisory/style/dependency warnings).
- Android 15 AOSP emulator, 1080×2340 / 420 dpi: 6/6 instrumentation tests passed.
  The suite covers slow import across recreation, editing/recreation/save,
  disable-all preserving tuning and provider output, actual scope instructions,
  preview-only disabled toggles, and legacy heartbeat identity migration.
- Early emulator cold-boot SystemUI ANR blocked one run; cleared and reran. UI tests
  then exposed status overlays intercepting clicks; replaced by nonblocking system
  notices. Standalone test document provider moved to Java to avoid dependence on
  instrumented app classes. The complete suite passed after those repairs.
- Unauthorized shell provider query rejected; packaged legacy metadata/entry and
  APK signature checked. Light/dark emulator screen inspection performed.
- Independent review found import-result loss on recreation; retained ViewModel
  fixes it and its follow-up review found no further important introduced defects.
- Exact user firmware recorded in DEVICE-TARGET. No physical Samsung hook tests or
  guessed new Launcher/system_server hooks; seven transitions remain pending.
